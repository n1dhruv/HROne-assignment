# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `/health` | Always returned `ok`, even when MongoDB was unavailable. | Call it when MongoDB is down. | Added a MongoDB ping and return 503 if it fails. |
| 2 | `GET /employees` | Wrong page skip and no page limits. | Page 1 skipped records; page sizes above 100 were accepted. | Used `(page - 1) * page_size`, required page >= 1, and limited page size to 1-100. |
| 3 | `GET /employees` | Total ignored the department filter, and results were not sorted. | Filter by department and check the total and employee order. | Used the same filter in `count_documents(q)` and sorted by `emp_code` ascending. |
| 4 | `EmployeeIn` | Employee fields had no proper validation. | Send code `ABC`, an empty name, an invalid email, shift `25:00`, equal shift times, or date `2026-02-30`. | Required `EMP` plus 4-6 digits, names of 1-100 characters, departments of 1-50, the email pattern with a 120-character limit, valid and different `HH:MM` shift times, and a real `YYYY-MM-DD` joining date. |
| 5 | `PunchInIn` | Bad timestamps and any status were accepted. | Send seconds, a float, a string, null, an out-of-range timestamp, or status `ABSENT`. | Required a strict integer from 100000000000 to 4102444800000 when supplied; rejected null. Allowed only `PRESENT`, `WFH`, and `ON_DUTY`, with `PRESENT` as default. Leaving the timestamp out still uses now. |
| 6 | `POST /attendance/punch-in` | Unknown employees could cause a server error, and punch times kept milliseconds. | Send an unknown employee code or a timestamp ending in 900 milliseconds. | Returned 404 for unknown employees and used `(punched_at // 1000) * 1000` to remove milliseconds before converting to UTC for storage and calculations. |
| 7 | `GET /attendance` | Dates, status and page values were not checked. | Send an invalid or reversed date range, an unknown status, `page=0`, or `page_size=101`. | Checked date format, real dates and date order. Allowed the five attendance statuses, page >= 1, and page size 1-100. Bad values return 422. |
| 8 | `attandance_date` | Attendance dates did not follow IST and the overnight rule. | For a 22:00-06:00 shift, punch in at 01:00 IST. | Added a helper that uses the IST date. For overnight shifts, a punch before the shift end uses yesterday's date, as required by R1. |
| 9 | `dt_to_ms` | Datetimes were returned instead of epoch milliseconds. | Check the time fields in a response. | Added a helper to convert datetimes into integer epoch milliseconds for responses. Naive MongoDB datetimes are treated as UTC. |
| 10 | `create_indexes` | The app created no indexes for employee and attendance queries or duplicate checks. | Start the app and check the indexes in both collections. | Added startup indexes on `employees` and `attendance_logs`, including unique employee codes and unique `(emp_code, date)` records. Running startup again keeps the same indexes. |
| 11 | `compute_late_minutes` | Punch times were compared with IST shift times without converting the timezone. | For a 09:30 shift, a 04:35 UTC punch should count as 10:05 IST and be 35 minutes late. | Treated times without a timezone as UTC and converted punch times to IST before calculating late minutes. |
| 12 | `GET /attendance` | Loaded all matching records and sorted only by date. | Request a small page with several employees on the same date. | Moved sorting and pagination to MongoDB: date descending, employee code ascending, then `skip((page - 1) * page_size)` and `limit(page_size)` to read only one page. |
| 13 | `compute_work_hours` | `round()` did not follow the required half-up rounding rule. | A duration of 162 seconds is 0.045 hours and should round to 0.05. | Used `Decimal` with `ROUND_HALF_UP` and `0.01` to round work hours to two decimal places. |
| 14 | Employee creation and punch-in | Parallel duplicate requests could both pass the check before saving. | Send two identical requests at the same time. | Used unique indexes and caught `DuplicateKeyError`. One request saves and returns 201; the duplicate returns 409. |
| 15 | `compute_overtime` | Timezones, overnight shift endings and the 30-minute minimum were handled incorrectly. | For a 22:00-06:00 shift, a 06:40 punch-out should give 40 overtime minutes. Anything below 30 minutes should give 0. | Compared times in IST, moved overnight shift endings to the next day, and counted overtime only from 30 whole minutes onward. |
| 16 | `compute_late_minutes` | The grace-period check dropped seconds too early, and overnight punches used the wrong shift start date. | For a 09:30 shift, 09:40:00 gives 0 late minutes, but 09:40:01 gives 10. | Checked the 600-second grace period before flooring minutes and used the previous day's shift start for overnight punches before the shift end. |

Also note anything you looked at and decided was **not** a defect, and why.

In `compute_work_hours`, subtracting punch-in from punch-out is correct when both times use UTC. Converting both to IST would give the same duration, so that conversion was not needed.
